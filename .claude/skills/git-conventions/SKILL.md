# Git-конвенции

## Commit message

- Следуй **Conventional Commits**: `feat`, `fix`, `chore`, `refactor`, `test`, `docs` и т.д. Указывай scope при изменении конкретного модуля/слоя (например, `chore(deps): Обновление зависимостей`).
- Используй русский язык.
- Начинай описание после двоеточия с существительного действия: `Добавление`, `Обновление`, `Настройка`, `Удаление`, `Включение`, `Отключение`, `Создание`, `Переработка`, `Доработка`, `Использование`, `Адаптация`.
- Не пиши глагол в повелительном наклонении или прошедшем времени: не `Добавь`, не `Исправь`, не `Обнови`, не `Добавил`, не `Исправил`, не `Обновил`.
- Действие `Добавление` можно опустить, если коммит `feat:` и из его сути понятно, что это добавление. Например, не `feat: Добавление параметра ignores`, а `feat: Параметр ignores`.
- Делай subject коротким и конкретным.
- Имена файлов, пакетов, компонентов, конфигов и технические идентификаторы оборачивай в backticks: `AGENTS.md`, `tsdown`, `eslint-plugin-unicorn`, `ignores`.
- Description старайся не писать, так как его содержимое должно быть понятно из сообщения коммита. Используй его только в крайних случаях.

## Pull Request

- Pull Request всегда проходят Squash & Merge, поэтому их названия должны полностью соответствовать стандартам для названий коммитов (описаны выше).
- Описание должно быть максимально кратким и содержательным. Оно должно описывать только изменения, внесенные в код.
- При создании PR выставляй ему соответствующие Labels, Assignee выставляй @ExEr7um.
